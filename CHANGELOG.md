# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The project will use [Semantic Versioning](https://semver.org/) from the first release (`v0.x.y`, [ENG-11 §5](docs/engineering/11_BRANCHING_AND_RELEASE_STRATEGY.md#5-versioning)). Release automation (release-please) may take over maintaining this file later (ENG-11 §6). Trading ruleset changes will also be recorded in `python-engine/rulesets/CHANGELOG.md`.

No release has been tagged yet. The entries below come from the merged git history.

## [Unreleased]

### Added

- Strategy library programme (ADR-018, documentation only): the 12-strategy roadmap and master tracker, development process and acceptance checklist, future adaptive-engine architecture (`docs/development/`); a page per strategy and a strategy template (`docs/strategies/`); independent backtesting standards, validation criteria (proposed), research data limitations and an experiment registry (`docs/research/`). No code changed.
- Dependency-audit exceptions (ENG-10 §4.6): `.github/security-exceptions.json` and `.github/scripts/check_npm_audit.py` (tested). A high/critical npm advisory fails CI unless it has a complete, unexpired exception. First entry: picomatch ReDoS `GHSA-fc5q-39xc-vjpf`, which affects every published version and reaches only dev tooling (production audit is clean); expires 2026-12-18.
- Frontend intraday screens on sample data (restructuring): session clock with phases and countdowns (entry cutoff, session-end exit), "Today's risk" per book on the dashboard, intraday "Risk and limits" settings, scanner "Valid until" column, `/portfolio` framed as Active trades.
- Frontend intraday data model (restructuring): `Candle` timestamps, `Timeframe` 5m/15m/1D, `StockAnalysis` intraday series, session levels, 15m context and signal validity; sample 5m/15m bars from a TypeScript port of the seeder (parity-tested); the price chart reads IST, draws session separators, previous-day levels and the opening range; the analysis panel shows signal timing, 15m context and a Session block. Sample data is a 14:00 IST snapshot with no forming or future bars.
- OpenAPI 0.2.0 (T-I09): intraday shared schemas (timestamps with +05:30, 15m context, session levels, signal validity), TRD-05 risk response, new endpoints R2 `GET /api/v1/risk/today` and X11 `GET /api/v1/positions/live`; 90 operations, coverage-checked against ARC-04.
- Intraday schema (T-I09, ADR-015): migration `2026_11_17_000001` moves bars to `bar_start` with 1m/5m/15m/1D timeframes, archives bar corrections in `candle_revisions` (trigger), turns snapshots into bar-range references, links several inputs per analysis run, adds timestamps to derived, trading and backtest rows, and adds the intraday risk limits to `risk_profiles`. Seeders now activate `pa-intraday 0.1.0` (retire `pa-core`), seed the NSE calendar mechanism (holidays not yet loaded, labelled unverified) and generate DEMO 5m/15m bars consistent with the daily bars. Engine contracts (risk sizing with account state, analysis by bar close) and the read model (34 tables) follow.
- Product documents revised for the personal intraday direction: vision, BRD and PRD v0.2.0 (single owner, NIFTY 50 intraday, account limits, session rules; SaaS features deferred), a trading-day user journey, onboarding deferred, feature catalog and UI/UX additions (freshness, session clock, limit banners, intraday chart time axis).
- TRD-06/07 v0.2.0 (intraday backtesting and paper trading): 5m bar replay with session-bounded account limits and session-end exits, an intraday cost schedule (to verify), walk-forward and forward-paper validation, bar-close paper processing with a session-end pass.
- TRD-05 v0.2.0 (intraday risk): ₹50,000 position cap, 0.5% risk, daily loss / consecutive-loss / open-position / open-risk limits that block plans, derived account state per book and session, next-bar entry-gap and session-end exit rules; worked examples at ₹1,00,000 capital.
- TRD-04 v0.2.0 (intraday setups): opening range breakout, previous-day high break (low break informational), breakout-retest on zones and session levels, a 15m context filter, session-bounded setups with the entry cutoff, an intraday target ladder and `paqs-intraday-0.1.0`; trend continuation and sweep reversal specified for after validation.
- TRD-02/03 v0.2.0 (intraday): structure and zones per timeframe, 15m context aligned to 5m bars without look-ahead, session handling and a repainting checklist, session reference levels (previous-day levels, opening range, session high/low); matching TRD-08 vectors.
- TRD-01 v0.2.0 (intraday): 5m setups with 15m and daily context, closed bars only, higher-timeframe alignment without look-ahead, session-bounded trading (opening range, entry cutoff, session-end exit), and ruleset `pa-intraday 0.1.0` (41 hypothesis parameters, engine and seeder copies checked in CI). `pa-core 0.1.0` retired to an appendix.
- ADR-015: intraday time model (bars keyed by `bar_start`, 1m/5m/15m/1D, completed bars only, revision history) and snapshots by reference (bar range + content hash, several inputs per run). Target schema in ARC-03 §2.2, API time conventions in ARC-04 §2.9, intraday ingestion in ENG-05 §12.
- ADR-014: PriceAction AI becomes a personal intraday price-action workstation (NSE cash, NIFTY 50, 15m structure + 5m setups, daily bars as context, long-only actionability, manual execution, account-level risk limits). Roadmap milestones M2–M10 are replaced by I0–I8; M1 is complete.
- Third-party GitHub Actions are pinned by commit SHA with a version comment (`setup-php`, `setup-uv`, `gitleaks-action`, `paths-filter`, `setup-buildx-action`); GitHub-owned `actions/*` stay on version tags (ENG-09 §6). Dependabot continues to update them.
- CI hardening (T-105): `ci-gate` only passes when every needed job is `success` or `skipped` by its path filter, `changes` succeeded and (on PRs) the title check succeeded; migration changes now trigger the engine schema-diff; `contracts/scripts/check_ruleset_hash.py` verifies that `pa-core 0.1.0` is identical in `python-engine/rulesets/`, the backend seeder data and TRD-01 §6. ### Changed

- Frontend status tones: lifecycle states use `success/warning/destructive/info/neutral` instead of the brand accent and market colours; `MetricCard`, `EmptyState`, `Segmented` and `PageContainer` replaced by the standard components. Fixed a chart race where the initial visible range could apply before candles loaded.
- `users` migration replaced the stock Laravel one: UUID primary key, `citext` email, status and soft delete; no `name` (moved to `user_profiles.display_name`) and no sessions table (Redis). Local dev databases need `make reset`.
- `make test-backend` now runs against a dedicated `priceaction_test` database using the schema-owner role, so migration and constraint tests can run.
- Frontend runtime aligned with Node 26 (Docker image, CI, `@types/node`) (PR #3, #11).
- Dependency updates: ESLint 10, frontend minor/patch group, GitHub Actions group (PR #5, #6, #7).
- Pinned PHP, Python, TypeScript and `@types/node` major versions in Dependabot to match the documented runtimes (PR #10).

### Fixed

- Frontend lockfile regenerated on Linux for CI compatibility.
