## 1. Purpose

Defines the mandatory test catalogue for the trading engine. Every test ID below must exist as an automated pytest case in `python-engine/tests/trading/` and run in the required CI check `python-engine / trading-tests` ([ENG-10](../engineering/10_GITHUB_ACTIONS_CI_CD.md)). A pull request that changes any file under `python-engine/app/domain/` cannot merge with a failing or skipped test from this catalogue.

## 2. Test design rules

| ID | Rule |
|---|---|
| TV-R1 | Fixtures are **hand-built candle tables** (CSV in `tests/fixtures/candles/`) with expected outputs written by hand from the spec, not generated by the code under test. |
| TV-R2 | Every rule in TRD-02..05 that has a numeric threshold gets a boundary test: just below, exactly at, just above. |
| TV-R3 | Golden-file tests: a set of real-shaped snapshots (≥ 10 instruments, anonymised or demo data) with committed expected JSON output. A diff in golden output requires a ruleset version bump. |
| TV-R4 | Property-based tests (Hypothesis library) for invariants (no look-ahead, rounding direction, quantity bounds). |
| TV-R5 | Tests reference the spec section in their docstring, e.g. `"""TRD-02 §3.4"""`. |

## 5. CI enforcement

- Job `python-engine / trading-tests` runs `pytest tests/trading -m "not slow"` on every PR touching `python-engine/**`, `docs/trading/**` or shared contracts.
- Job `python-engine / golden` runs golden-file tests; failures print the diff.
- Nightly scheduled workflow runs the full property-based suite with a larger example budget.
- A test-catalogue completeness check (`scripts/check_trading_test_catalogue.py`, M3) fails CI if any `TV-*` ID in this document has no matching test marker.

## 6. Parameter promotion criteria (proposed, needs sign-off — OQ-TRD-03)

A parameter set may be marked `VALIDATED` for a ruleset version when, on the OOS segment of TRD-06 §9:

1. ≥ 100 filled trades across the universe;
2. Net expectancy > 0.10 R;
3. Profit factor (net) > 1.2;
4. Max drawdown ≤ 2× the IS max drawdown;
5. `survivorship_bias_risk = false`.

These are acceptance gates for promotion, not performance claims.
