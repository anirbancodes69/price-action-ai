## 1. Purpose

Uniform error taxonomy, retry policy and structured logging across frontend, Laravel, engine and workers.

## 2. Error taxonomy

| Class | Examples | HTTP | Retry? | User message |
|---|---|---|---|---|
| Validation | `VALIDATION_FAILED`, `STOP_NOT_BELOW_ENTRY` | 422 | No | Field-level / specific |
| Domain state | `PLAN_NOT_EDITABLE`, `ENTRY_WINDOW_ELAPSED`, `ANALYSIS_STALE` | 409 | After reload | Specific |
| Auth | `UNAUTHENTICATED`, `FORBIDDEN`, `ENTITLEMENT_REQUIRED` | 401/403 | No | Login / upgrade prompt |
| Not found | `NOT_FOUND`, `NO_ANALYSIS_AVAILABLE` | 404 | No | Empty state |
| Rate/quota | `RATE_LIMITED`, `QUOTA_EXCEEDED` | 429 | After `Retry-After` | Time until reset |
| Dependency | `ENGINE_UNAVAILABLE`, `PROVIDER_UNAVAILABLE`, `PROVIDER_RATE_LIMITED` | 503 | Yes (backoff) | "Temporarily unavailable" |
| Provider auth | `PROVIDER_AUTH_EXPIRED` | 409 | No (user reconnect) | Reconnect prompt |
| Contract | `ENGINE_CONTRACT_ERROR` | 502 | No | Generic + request id; alert |
| Engine result status | `INSUFFICIENT_HISTORY`, `INVALID_INPUT` | 200 (status field) | No | Explained in UI |
| Internal | `INTERNAL_ERROR` | 500 | No | Generic + request id; alert |

Domain error codes are listed once in a shared registry file per service (`backend/app/Shared/Http/ErrorCodes.php`, `python-engine/app/errors.py`) and asserted equal by a CI test against the OpenAPI enum.

## 3. Retry policy

| Operation | Policy |
|---|---|
| Laravel → engine sync | No automatic retry for POST; 1 retry for idempotent GET after 200 ms |
| Worker → Kite | Exponential backoff 1/2/4/8 s + jitter, max 4, only for 429/5xx/timeouts |
| Worker → LLM | 1 retry after 2 s; then fallback |
| arq jobs | `max_tries` 3 for transient errors (`TransientError` subclass); permanent errors fail immediately |
| Laravel jobs | `tries=3`, `backoff=[10, 60, 300]`; failed jobs to `failed_jobs` + alert if > N/hour |
| DB serialization failures | Retry transaction up to 3 times |

## 4. Structured logging

- Format: JSON lines to stdout (Docker log driver collects). Laravel: Monolog JSON formatter; Python: structlog JSON; Next.js: minimal server logs (pino or console JSON) for SSR errors.
- Mandatory fields: `timestamp` (UTC ISO), `level`, `service` (`frontend|backend|engine|engine-worker`), `env`, `request_id`, `tenant_id` (when known), `user_id` (when known, never email), `event` (snake_case message key), `duration_ms` (for requests/jobs), `job_id`/`run_id` where applicable.
- Levels: `debug` (local only), `info` (state transitions, job start/end), `warning` (handled anomalies, data-quality WARN), `error` (failed operations), `critical` (data integrity or security events).
- Correlation: `X-Request-Id` from edge or generated by Laravel middleware; forwarded to engine; included in job payload metadata so worker logs correlate.

## 5. Redaction (mandatory)

Processors redact values of keys matching `/(pass(word)?|secret|token|authorization|cookie|api[_-]?key|request_token|access_token)/i` and strip query strings containing them. A test in each service logs a payload containing secrets and asserts they are redacted. LLM prompts are not logged in production (ARC-07 §11).

## 6. Error tracking

Unhandled exceptions from all services go to the error-tracking service (choice in OPS-03) with `request_id`, release version and environment; PII scrubbing enabled. Frontend error boundaries report client errors.

## 7. Audit vs application logs

Audit logs (`audit_logs` table) are business records with retention guarantees; application logs are operational and short-lived (OPS-04). Never rely on application logs for audit.

## 8. Frontend error UX

Typed `ApiError` in the adapter → route `error.tsx` for page loads, inline errors for forms, toasts for background actions; always show `request_id` in a copyable "Reference" for support.
